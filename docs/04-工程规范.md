# 04 工程规范

> 关系：00 概要设计规定模块之间**交换什么**（接口、DTO、错误码、事件）；本文规定模块内部**怎么写**。冲突时以 00 为准，并同步修改本文。
> 执行：能交给工具检查的由工具检查（§10）；工具查不出的列入评审清单（§11）。
> 来源：沿用 AutoNote `docs/04-工程规范.md` 的规则，删去与 aether 无关的部分（Web Worker、Hono）。

## 1. 通用设计原则

### 1.1 面向接口

- **跨越边界的依赖一律面向接口**。aether 的边界：宿主 ↔ aether（`KitHost`）、Chat ↔ 工具（`ToolExecutor`、`Approver`）、Chat ↔ 存储（`ConversationStore`）、UI ↔ 后端（`*Port`）、UI ↔ 日志（`KitLogger`）。
- **接口由使用方定义**，放在使用方模块里（例如 `ToolExecutor` 定义在 aether-chat，由接入层实现）；不允许"先写实现类再抽接口"。
- **构造参数注入**。服务与状态类不在内部引用具体实现的单例；只有组合根（宿主 `main.rs` / 根组件、`tauri-plugin-aether` 的 `Builder`）装配具体实现。
- 判断标准：**测试时需要替换它，或跨越上面列出的边界** → 定义接口。只有一个实现且不跨边界的内部模块不定义接口（例如 `secret` 按平台 `cfg` 选择实现，不建 trait）。

### 1.2 面向对象

- **有状态、有行为、有不变量**的写成类（TS）或结构体 + `impl`（Rust），例如 `Store`、`Runner`、`McpServer`、`RunSession`。纯变换写成函数（`infer`、`api_base`、`mask_secret`）。
- 单一职责：一个类型围绕一个聚合；超过约 400 行（TS）/ 600 行（Rust，不含测试）按职责拆分，不拆须在评审中说明理由。
- 组合优于继承。TS 类最多继承一层，仅限 `KitClientError extends Error`；Rust 用 trait + 组合。
- 封装：字段默认私有（TS `#field`，Rust 默认私有），对外只暴露只读视图和意图明确的方法（`setToolApproval(server, tool, approval)`，而不是 `setTools(list)`）。
- 不变量在构造函数和写方法里强制检查，违反时返回 `Err` / 抛 `KitClientError('bad_request')`，对象不进入非法状态。

### 1.3 模块化

- 每个模块一个公开入口（TS `index.ts`，Rust `lib.rs`），只导出契约；内部文件不被外部直接引用（`no-restricted-imports`、Rust 默认私有 `mod`）。
- 依赖方向严格单向（00 §3），禁止循环依赖（`import-x/no-cycle`、cargo、`scripts/check-deps`）。

## 2. 日志规范

### 2.1 共同规则

- **结构化**：事件名 + 扁平字段。事件名小写点分 `<模块>.<对象>.<动作>`，如 `providers.probe.failed`、`chat.run.finished`、`mcp.server.forbidden`。同一事件名的字段集合固定。
- **级别语义**：

  | 级别 | 什么时候用 | 例子 |
  | --- | --- | --- |
  | `error` | 操作失败且需要人处理，或可能丢数据 | 迁移失败、日志写盘失败、`internal` 错误 |
  | `warn` | 降级或已自动恢复 | MCP 某服务连接失败但其他工具可用、去掉 tools 重试一次、ingest 拒绝 |
  | `info` | 生命周期与关键节点，每个用户操作最多一条 | 启动与数据根、运行结束、MCP 服务启停、密钥被显示 |
  | `debug` | 排查用，默认不输出 | 单次请求耗时、队列长度 |

- **禁止记录**：密钥、token、请求头凭据、URL 中的凭据 query、用户输入正文、模型输出、技能正文、工具参数原文。只记 ID、长度、状态码、耗时、计数。凭据字段整项省略，不保留首尾片段（展示用的打码值也不进日志）。
- **不在循环里逐条记**，汇总为一条（`count`、`duration_ms`）。
- **每个错误只记一次**：在最终处理它的那一层记（Tauri 命令边界、运行终态）；中间层只传递并补充上下文。

### 2.2 TypeScript

- `KitLogger` 接口：`debug | info | warn | error(event: string, fields?: LogFields): void`，由 `KitContext` 注入。
- 除 `createLogger` 实现外**禁止 `console.*`**（`no-console: error`）。前端日志批量经 `logs_ingest` 写入 Rust 日志文件（10 文档 §10）。

### 2.3 Rust

- 只用 `tracing`，字段写在宏参数里：`tracing::info!(run_id = %id, rounds, "chat.run.finished")`。
- 每个 Tauri 命令入口 `#[tracing::instrument(skip_all, fields(command = "..."), err(level = "warn"))]`：失败自动记一条，其他层不重复记。参数一律 `skip_all`，需要的非敏感字段显式列出。
- 核心 crate 只发事件，不安装订阅器（00 §7.4）。
- 禁止 `println!`、`eprintln!`、`dbg!`（clippy `print_stdout`、`print_stderr`、`dbg_macro`）。例外：日志系统初始化之前的启动失败，以及 `examples/cli` 的用户输出，均须 `#[expect(clippy::..., reason = "...")]` 标注。

## 3. 异常规范

### 3.1 共同规则

- **两类错误**：
  1. **预期错误**：输入非法、未配置、冲突、限流、上游失败、取消。用 00 §7.2 的 `KitErrorCode`，调用方按 `code` 分支，用户看到翻译后的 `errors.<code>`。
  2. **程序错误**：违反不变量或 bug。不做分支处理，冒泡到边界，记一条 `error`（含 `error_id`），用户看到通用文案与错误 ID。
- **不吞错误**：每个 `catch` / `Err` 分支只能做三件事之一：按具体 `code` 处理并恢复；补充上下文后重新抛出；在最终处理层记日志并通知用户。禁止空 `catch {}`（注释也不能豁免）。
- **不靠文案判断类型**：禁止 `message.includes(...)`；只按 `code` 与类型判断。
- **输入非法就报错，不猜测**：不认识的枚举值、越界参数一律 `bad_request`，不擅自回退默认值。
- **两条通道不重复**：Tauri 命令在接受请求前的失败走命令返回值；运行接受后的失败只走 `end` 事件（00 §4）。

### 3.2 TypeScript

- 跨越端口边界抛出的只有 `KitClientError`。`@ouraihub/aether-ui/tauri` 在边界把 Tauri 返回的错误对象转换成它；组件与状态类不接触原始错误。
- 只 `throw` `Error` 实例；`catch (error)` 中 `error` 为 `unknown`，先用 `isKitClientError(error)` 收窄。
- `<svelte:boundary>` 只兜渲染与 effect 异常；事件处理器和异步请求的错误在状态类里处理并通知用户。

### 3.3 Rust

- 核心 crate 对外返回 `aether_support::KitError`（00 §12 说明为何统一一个类型）；内部可用私有 thiserror 枚举，在模块边界 `From` 转换。
- 底层路径、SQL、凭据不进 `details`，原因只写脱敏日志。
- 非测试代码禁止 `unwrap`、`expect`、`panic!`、`unreachable!`、`todo!`、`unimplemented!`。测试模块用 `#[expect(clippy::unwrap_used, reason = "...")]` 显式豁免。
- 用 `?` 传播；补充上下文用 `.map_err(...)`。库 crate 不用 `anyhow`。
- `Mutex` 中毒映射为 `internal`，不 panic。

## 4. TypeScript

- 编译选项：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`noImplicitOverride`、`verbatimModuleSyntax`、`isolatedModules`、`noUnusedLocals/Parameters`。
- 不用 `any`，用 `unknown` 再收窄；不用非空断言 `!` 绕过 `undefined`。
- 数据形状用 `interface`，联合与工具类型用 `type`。状态机用标签联合（`kind`），`switch` 的 default 写 `const _exhaustive: never = x`。
- 不用 TS `enum`，用 `as const` 对象 + 字面量联合。仅类型导入写 `import type`（`consistent-type-imports`）。
- DTO 类型只来自 `ports/generated`（ts-rs），不手写重复定义。
- 函数参数不修改；公开只读视图用 `readonly T[]` / `ReadonlyMap`。
- 所有 Promise 必须 `await` 或显式 `void` 并附注理由（`no-floating-promises`、`no-misused-promises`）。可取消操作接收 `AbortSignal`。
- 命名：类型与类 PascalCase，变量函数 camelCase，常量 UPPER_SNAKE，文件 kebab-case（Svelte 组件 PascalCase，状态类 `*.svelte.ts`）。布尔值以 `is`/`has`/`can` 开头。

## 5. Svelte 5

- **UI 组件用 shadcn-svelte**：动 UI 前先读仓库内 `.claude/skills/shadcn-svelte/SKILL.md` 及其 `rules/`，按其规则组合现有组件（16 文档 §1）；新页面或改版先按 `.claude/skills/hallmark` 做设计检查。不手写 shadcn 已有的组件，不覆盖组件内部颜色与字体，不手写覆盖层 `z-index`。

- **只用 runes**：`$state`、`$derived`、`$effect`、`$props`、`$bindable`。禁止 `export let`、`$:`、`on:event`、`<slot>`、`createEventDispatcher`、用 `svelte/store` 做状态。编译警告视为错误（`svelte-check --fail-on-warnings`）。
- **状态放在 `*.svelte.ts` 的类里**（如 `RunSession`）：字段 `$state` / `$state.raw`，派生用 `$derived`；对外只读 getter + 意图明确的方法，组件不直接给字段赋值。
- 大集合（模型列表、消息列表）用 `$state.raw` 整体替换。
- `$effect` 只用于订阅与 DOM 同步，有资源就返回清理函数；不形成读写同一状态的循环；异步结果用 `AbortSignal` 或 generation 丢弃过期结果。能用 `$derived` 的不用 `$effect`。
- **依赖注入走 context**：`createContext<T>()` 生成类型安全的 `[get, set]`；宿主根组件 `set`，容器组件 `get`。不用模块级单例。
- **Props**：`let { a, b = 1, onChange }: Props = $props()`，`Props` 为具名 `interface`；回调 prop 命名 `onXxx`；默认单向，确需双向才 `$bindable`。
- **内容分发**用 snippet（`Snippet<[Args]>`）；**DOM 行为**用 `{@attach}`，不用 `use:`。
- **展示组件**只经 props 收数据、经回调报告，不取 context、不调端口；**容器组件**（每个能力的 `*Settings` / `ChatPanel`）从 context 取端口与状态类。
- 禁止 `{@html}`（`svelte/no-at-html-tags`），用 `{@attach}` + 已清洗的 HTML。
- 可访问性：交互元素用原生 `<button>` / `<input>`；图标按钮有 `aria-label`；弹窗关闭后焦点回到触发元素；颜色不是唯一信息来源。

## 6. Tauri 2

- **命令只做转发**：反序列化 → 调用核心 crate → 转换错误 → 返回。业务逻辑在核心 crate。
- **命令全部 `async`**，同步 SQLite / 文件操作放进 `tauri::async_runtime::spawn_blocking`；返回 `Result<T, KitError>`。
- **状态**：`app.manage()` 注册 `Arc` 包裹的服务对象；命令用 `State<'_, T>` 取用；可变部分在服务内部加锁，不把 `Mutex` 暴露给命令；跨 `.await` 不持有 `std::sync::Mutex`（`await_holding_lock`）。
- **流**：高频、有序、单一接收方的数据（运行事件、探测进度）用 `tauri::ipc::Channel<T>` 参数；不用全局事件广播。Channel 发送失败视为取消。
- **权限**：每条命令一个权限标识，按能力分组（15 文档 §5）；示例宿主的 capability 只引用实际用到的分组；危险命令单独分组且不在默认集合。CSP 保持严格，不开 `unsafe-eval`。
- **插件**：只用官方插件；Rust crate 与 npm 包的主次版本一致，版本写死。
- **前端访问**：只有 `@ouraihub/aether-ui/tauri` 调用 `invoke` / `Channel`；其余代码只接收端口接口。
- **生命周期**：退出、窗口销毁时取消运行与后台任务（15 文档 §6）；不留未管理任务。

## 7. Rust

- edition 2024；工具链由 `rust-toolchain.toml` 锁定；lints 在 workspace 统一配置，各 crate `[lints] workspace = true`。
- 分层：核心 crate 不依赖 tauri（00 §3）。
- 借用优先：参数用 `&str`、`&[T]`、`&Path`；需要所有权才传 `String`/`Vec`；不做无意义的 `.clone()`。
- 类型驱动：ID、修订号等用 newtype 并在构造时校验；状态机用 `enum`，`match` 穷尽，不写 `_ =>` 兜底。
- trait 只用于 §1.1 的接缝，不为单实现定义 trait。
- SQL 只用参数绑定（`params![]`），禁止 `format!` 拼接值；多条写入放在一个事务；迁移只追加。
- `unsafe_code = "deny"`；唯一例外是平台凭据 FFI（`aether_support::secret`），模块级 `#[allow(unsafe_code, reason = "...")]`，每个 `unsafe` 块写 `// SAFETY:`。
- 公开项写 `///` 文档（`missing_docs`）；返回 `Result` 的公开函数写 `# Errors`。
- 敏感类型（`Connection`、明文密钥）手写 `Debug`，不派生 `Serialize`。

## 8. 测试规范

- 测**行为与契约**：边界、不变量、状态转换、错误码、优先级。不测实现细节、不测转发、不测源码文本、不写"没有抛错"的空断言。
- 核心 crate：单元测试 + 本地可控上游的集成测试（`tests/`）。接入层：在示例宿主真实窗口验收。前端：状态类在 node 中 `new` 出来测，注入 `createFakePorts()`；组件用 `@testing-library/svelte` + jsdom 测交互与可访问性。
- 修 bug 先写失败的复现测试，修好后保留。
- 测试确定、隔离、不访问外网；临时目录用 `tempfile`；不写开发者真实数据。

## 9. 代码与注释

### 9.1 磁盘清理

Rust 编译产物会长到数 GB。定期运行 `scripts\clean.bat`（`--deep` 同时删 `node_modules`，`--yes` 跳过确认）：删除 `target\`、各示例 `src-tauri\gen`、前端构建输出；保留任何 `data\` 目录与 junction；仓库内有进程占用文件时拒绝执行；不碰共享的 `%USERPROFILE%\.cargo` 与仓库外的 `CARGO_TARGET_DIR`。

### 9.2 注释

- 注释写"为什么"，不写"做了什么"。陷阱和反直觉的决定必须注释，并指向设计文档章节。
- 有意识的简化写 `// ponytail: <上限>，<何时升级>`，例如并发执行、估算 token。
- 标识符、注释、提交信息中不出现参考项目名；需要说明来源时写具体函数或文件。

## 10. 工具强制

| 规则 | 工具 | 位置 |
| --- | --- | --- |
| `console.*`、空 `catch`、`any`、未处理 Promise、类型导入 | ESLint（`no-console`、`no-empty`、`no-explicit-any`、`no-floating-promises`、`no-misused-promises`、`consistent-type-imports`） | `eslint.config.js` |
| Svelte 4 语法、`{@html}`、编译警告 | `eslint-plugin-svelte`、`svelte-check --fail-on-warnings` | 同上；`packages/ui` typecheck |
| 循环依赖 | `import-x/no-cycle` | 同上 |
| 非 `tauri/` 目录引用 Tauri API | `no-restricted-imports` | 同上 |
| 硬编码颜色类 | 自定义规则 `aether/no-hardcoded-color` | 同上 |
| unwrap/expect/panic/todo、print、dbg、unsafe、文档、`#[allow]` 无理由 | workspace lints + `clippy -D warnings` | 根 `Cargo.toml` |
| crate 依赖方向、feature 独立编译 | `scripts/check-deps` | K0-2 |
| DTO 与生成结果一致 | `pnpm kit:dto-check` | C1-1 |
| 两种语言键集合一致、组件使用的键存在 | `pnpm kit:i18n`（`errors.<code>` 由 `Messages` 类型覆盖） | U1-1 |
| 格式 | `prettier --check`、`cargo fmt --check` | 根目录 |

## 11. 评审清单（工具查不出的部分）

- [ ] 跨边界依赖有接口吗？接口由使用方定义吗？具体实现只在组合根装配吗？
- [ ] 类型是否单一职责？字段私有？不变量在写方法中强制校验？
- [ ] 每个 `catch` / `Err` 分支属于 §3.1 的三种处理之一吗？错误只记录了一次吗？
- [ ] 日志事件名、级别符合 §2 吗？日志里有没有正文、密钥、token？
- [ ] `$effect` 能否改成 `$derived`？有资源的 effect 都有清理吗？
- [ ] 命令足够薄吗？业务逻辑在核心 crate 吗？
- [ ] 新测试在修复前失败、修复后通过吗？测的是行为吗？
