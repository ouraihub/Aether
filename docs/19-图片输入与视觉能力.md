# 19 图片输入与视觉能力

> 2026-10-15。共享合同；所有宿主复用本章类型、协议编码和界面。实施计划、任务与验收证据：AutoNote `docs/31-图片输入与视觉能力设计及开发规划.md`。参考 Cherry Studio（`src/shared/utils/model.ts` isVisionModel、`ModelDrawer/ModelClassificationControls.tsx`、`pages/home/Messages/homeMessageListAdapter.tsx` needsVision、composer paste/drop），不移植其 FileManager、AI SDK、OCR。

## 1. 视觉能力（一期，已实现 f9a037a）

- 能力在**配置时**确定，不在发送时猜：获取模型时按名称推断，用户在模型设置里可改，保存后即为准。Cherry 同样以 registry 目录为默认、用户 inputModalities 覆盖为准。
- 存储：`models.can_vision`（两宿主早已有列）。`Model`/`ModelSave`/`ProbedModel` 已含 `canVision`。
- `ModelOption.canVision: bool`（新增，ts-rs 生成）。Rust `Store::model_options` 与 Web `modelOptions` 都读该列。
- 推断：`infer.rs` / `infer.ts` 族表第三项为默认值；名称含 `vision`、`-vl`、`vl-`、`4v` 时为 true（`qwen-vl-max`、`Qwen2.5-VL`、`glm-4v`、`llama-…-vision`）。两侧共用 `packages/ui/fixtures/model-classify.json` 断言一致。
- 界面：`EndpointCard` 模型设置“可看图”开关；`ModelPickerDialog` 重新获取模型时保留已有 `canVision`；`ModelSelect` 能力标签与筛选首位为“视觉”（Eye 图标）。

## 2. 图片类型与上限（二期）

```text
ImagePart { mime: "image/png"|"image/jpeg"|"image/webp"|"image/gif", data: base64 }   // camelCase，ts-rs 导出
MAX_IMAGES = 4；单张解码后 ≤ 4 MiB；data 为标准 base64，无 data: 前缀
```

- `RunRequest.images?: ImagePart[]`（serde default 空；deny_unknown_fields 保持）。
- 历史展示：`Turn.images: ImageRef[]`，`ImageRef { mime, url: string | null }`；`url = null` 表示已过期。**历史接口从不返回 base64**，避免每次加载会话搬运大数据。
- `url` 由宿主生成：桌面为 `data:` URL（本地进程内，CSP 已允许 `img-src data:`）；Web 为同源鉴权路由 `/api/ai/kit/conversations/:id/turns/:turnId/images/:index`。

## 3. 校验（宿主入口与 Runner 双重）

1. 数量、MIME 白名单、base64 合法、解码大小；违规 `bad_request{field:"images", reason:"count"|"mime"|"size"|"encoding"}`。
2. `connection.can_vision == false` 且本轮（含重放的历史）带图：`bad_request{field:"images", reason:"vision_unsupported"}`，请求前失败、不建 turn、不出网。
3. 翻译动作不携带图片；`retry`/`regenerate`/@换模型复用源 turn 的图片（宿主读回原图，不从客户端重传）。

## 4. 协议编码（当前输入与历史 user 消息同一函数）

| 协议 | user content |
| --- | --- |
| openai-chat | `[{type:"text",text}, {type:"image_url",image_url:{url:"data:<mime>;base64,<data>"}}…]` |
| openai-responses | `[{type:"input_text",text}, {type:"input_image",image_url:"data:<mime>;base64,<data>"}…]` |
| anthropic-messages | `[{type:"image",source:{type:"base64",media_type,data}}…, {type:"text",text}]`（图在前，官方建议） |

- 无图时仍发送纯字符串 content，旧请求体字节不变。
- 过期图片不发送，也不插入占位文本。
- 不做 OCR、压缩、Gemini、文件 API 上传；不按图片估算 token（用户决定不考虑预算）。

## 5. 存储与临时清理

- 原图保留 `IMAGE_TTL_DAYS = 7`，到期由宿主定期删除字节，turn 本身保留。
- Rust `SqliteStore`：迁移 v4 新表 `turn_images(turn_id REFERENCES turns(id) ON DELETE CASCADE, idx, mime, data BLOB, created_at, PRIMARY KEY(turn_id, idx))`；`begin_action` 接收新输入的图片并原子写入；retry 新 turn 复制源 turn 的行（同事务）；`purge_images(older_than)` 删除过期行，插件在启动与每小时调用。
- `Message::User(String)` serde 形态不变（chat.db 旧行兼容）。图片不进 `messages` JSON，按 turn 另读；`RunInput.images` 为当前输入的图片，`RunInput.history_images: Vec<(usize, Vec<ImagePart>)>` 按 history 中 user 消息序号附带。
- 删除会话/turn 由外键级联删除图片。

## 6. 共享界面

- `ChatPanel` 输入卡片：附件按钮（`<input type=file accept="image/png,image/jpeg,image/webp,image/gif" multiple>`）、粘贴（`clipboardData.files`）、拖拽（`dataTransfer.files`）；缩略图条可逐张移除；超限即时提示不入队。
- 当前模型 `canVision=false`：附件按钮禁用并提示“当前模型不支持图片”；已附图时发送禁用。切到视觉模型自动恢复。
- `MessageItem` 用户消息上方显示缩略图（`url=null` 显示“图片已过期”占位）；点击新窗口打开原图（同源 url）。
- @ 列表：源 turn 带图时只列 `canVision` 模型（等同 Cherry needsVision）。
- 草稿恢复（发送失败）同时恢复图片。

## 7. 验证

Rust：三协议请求体、历史重放带图、过期不发、vision_unsupported 不出网、迁移旧库、retry 复制、purge。UI：粘贴/拖拽/移除/超限/非视觉禁用/@ 过滤。宿主：真实 HTTP 回环核对请求体，真实浏览器与 WebView2 发图、刷新历史、重新生成、过期后表现。
