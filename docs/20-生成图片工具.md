# 20 生成图片工具（generate_image）

> 2026-10-15。共享合同；实施计划与证据：AutoNote `docs/32-生成图片设计及开发规划.md`。参考 Cherry Studio：`composer/tools/definitions/generateImageTool.tsx`（开关）、`main/ai/tools/adapters/aiSdk/builtin/PaintingTool.ts`（`applies = 绘图模型已配置 && 开关打开`）、`shared/ai/generateImageTool.ts`、`chat/messages/tools/painting/MessageGenerateImage.tsx`。用户决定：**对话模型自己决定何时调用工具**（同 Cherry），绘图走 **OpenAI 兼容 `/v1/images/generations`**。

## 1. 交互

- 输入框「+」菜单：`上传附件`（已实现）、`生成图片`（开关，`aria-pressed`；打开后菜单外显示“生成图片”标签可一键关闭）。
- 未配置绘图模型：菜单项置灰，提示“请先在设置 › 默认模型中选择绘图模型”，并提供宿主设置入口（`onOpenSettings`）。
- 开关是**会话级 UI 状态**（同联网开关），发送时写入 `RunRequest.generateImage: true`；不持久化到会话，切换会话复位。
- 回复中：工具调用行显示“正在生成图片…”，完成后在该回复内渲染生成的图片（可点开原图），失败显示错误摘要；模型的文字说明照常流式显示。

## 2. 合同

```text
RunRequest.generateImage?: bool                         // 缺省 false
Turn.images 不变（用户输入图片）；新增 Turn.generated: ImageRef[]   // 本轮工具产出的图片，过期 url=null
工具名 generate_image；参数 { prompt: string(1..4000), size?: "1024x1024"|"1024x1536"|"1536x1024", image_ids?: string[](1..4) }
工具结果文本（喂回模型）："Generated N image(s)."；payload 仅供 UI：{ images: ImageRef[] }
```

- 绘图模型是宿主角色 `painting`（与 `chat`/`writing` 同一套角色设置），`ModelType = image` 的模型才可选。
- `applies`：`generateImage == true` 且 `painting` 角色已绑定；否则不把工具放进本轮目录。开关打开但未绑定 → `needs_config{reason:"painting_model"}`，请求前失败。
- 对话模型必须支持工具（`supportsTools != false`）；为 false 时开关置灰并提示。
- 改图（AutoNote docs/37）：绘图模型 `canVision = true` 表示支持参考图。运行准备时收集可用图片清单（仍有字节，从新到旧最多 8 张：本条消息输入图片（后附的在前），然后历史路径各轮从新到旧，每轮先生成图片、后输入图片，各自后者在前），编号 `image-1`…，写进工具描述（`Images you can pass in image_ids (newest first):` + 每行 `image-N: attached by the user in this message | attached in an earlier message | generated in an earlier reply`）；`image_ids` 为这些 id 的 `enum` 数组，`minItems 1`、`maxItems 4`。模型不支持或清单为空 → 参数里没有 `image_ids`。本轮刚生成的图片不在清单里。
- 执行时按 id 懒加载字节，检查顺序：模型不支持 → `bad_request{image_ids, unsupported}`；> 4 → `too_many`；不在清单 → `unknown`；字节已清理 → `expired`。错误照常作为工具失败回填。

## 3. 执行

- 请求：无 `image_ids` 时 `POST {painting.imageBaseUrl ?? baseUrl}/images/generations`，`{ model, prompt, size, n: 1 }`；有 `image_ids` 时 `POST {painting.imageEditBaseUrl ?? baseUrl}/images/edits`，`multipart/form-data`：`model`、`prompt`、`size`、`n=1`，单张字段 `image`、多张每张 `image[]`，文件名 `image-N.{png|jpg|webp|gif}` 带各自 MIME（桌面手写正文，Web 用 `FormData`；只由 multipart 边界决定 `content-type`）。两者都先加自定义头、后加 Bearer（绘图端点密钥，轮换并在 401/403/429 换钥）；同一地址策略（私网/回环需宿主允许）。**不发** `response_format`：gpt-image-* 不支持该参数、固定返回 b64（同 Cherry `hasDefaultResponseFormat`），其余模型可能返回 `url`。返回 `data[].b64_json`，或只有 `url` 时宿主下载一次（受同一地址策略与 4 MiB×1 上限），两条路径共用解析。
- 超时 120 s；取消随本轮取消。一次运行最多调用 2 次（防循环出图）。
- 生成的图片按 docs/19 §5 存储与 7 天清理：桌面写 `turn_images`（新增列 `kind TEXT NOT NULL DEFAULT 'input' CHECK (kind IN ('input','generated'))`，迁移 v5）；Web 写 `ai_turn_images`（同样新增 `kind`）与 R2。
- 历史重放：生成的图片**不**作为后续轮的模型输入（只保留工具调用与结果文本），避免每轮重复上传；需要基于它改图时，对话模型通过 `image_ids` 引用它（见 §2）。

## 4. 宿主分工

| 位置 | 内容 |
| --- | --- |
| Aether `aether-providers` | 角色 `painting` 解析为 `Connection`（复用 resolve） |
| Aether `aether-chat` | `generate_image` 工具规格、参数校验、images API 客户端（reqwest，复用 net 策略）、结果 → `ToolExecution::Ok{payload}` |
| Aether plugin | `RunRequest.generateImage`、`applies` 判定、执行时落库 `kind='generated'`、`Turn.generated` |
| Aether UI | 「+」菜单开关与未配置提示、工具行“正在生成图片”、回复内图片网格 |
| AutoNote Web | Worker 侧补工具调用循环（三协议 tool_calls 解析与 tool_result 回填，仅宿主内置工具，最多 4 轮），`generate_image` 执行、R2/D1 落库、`Turn.generated`、绘图角色设置 |
| AutoNote 桌面 | 角色设置增加“绘图模型”；`KitHost` 无需新工具代码（由插件提供） |

## 5. 不做

局部重绘（蒙版）/绘图页、多张批量、非 OpenAI 绘图协议、生成图片作为后续对话输入、费用统计。
