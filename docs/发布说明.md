# Aether 发布说明

## v0.1.2

### 范围

- 同步发布 `@ouraihub/aether-{contracts,core,ui,presets,worker}@0.1.2`，Rust workspace 与仓内示例同步版本；实际代码变化只在 `@ouraihub/aether-ui` 的聊天组件，其余包与 crate 只升版本号。
- 新增 `ModelEffortPicker`、`ReasoningSlider`、`ContextUsageStatus` 及 `model-effort`、`context-status` 纯函数导出；`ChatPanel` 输入栏改为「工具 → 模型胶囊 → 用量 → 发送」单行，头部不再有独立模型选择与力度控件。设计与行为合同见 [31](31-详细设计-模型力度选择与上下文状态.md)。
- `ChatPanelProps` 新增可选 `defaultModel`、`defaultReasoningEffort`、`onDefaultModelChange`；不传时隐藏「设为默认」，现有调用无需修改。
- 力度档位总按 off → max 排序，与宿主声明顺序无关；`purpose: 'chat'` 隐藏权限模式与技能，`agent` 保留。

### 接入与兼容性

- 同时使用的 Aether npm 包统一锁定 `0.1.2`。此前对 0.1.1 打补丁接入本组件的宿主，升级后删除补丁及其 `patchedDependencies` 项。
- 契约、DTO、数据库与存储版本均与 v0.1.1 相同，无新迁移；升级与回退步骤同 v0.1.1。

### 验证边界

- 组件改动经 PR #32 前端完整检查（310 个 UI 测试、svelte-check、lint、i18n、示例构建）与 Windows 完整 CI；发布工作流对版本提交重新执行 Windows/macOS/Linux 完整检查，全部成功才发布 npm。
- AutoNote 桌面/Web 与 Actora 已在本地以补丁形式实测 360/440/520/640px 宽度；未宣称 macOS/Linux 实际窗口交互已验证。

## v0.1.1

### 范围

- 同步发布 `@ouraihub/aether-{contracts,core,ui,presets,worker}@0.1.1`，Rust workspace 与仓内示例同步版本。Rust crate 仍为 `publish = false`，通过 Git tag/固定提交接入；本次不发布 crates.io，也不提供产品安装包。
- Worker MCP：401 返回路径式资源发现与最低基础 scope 提示；有效令牌缺少已注册的 `mcp:access` 时返回可重新授权的 `insufficient_scope` challenge。没有注册基础 scope 的部署不强制新增该权限。
- Worker MCP：较新客户端的 initialize 请求协商到服务端实际支持的 `2025-03-26`，不再直接拒绝；畸形版本仍拒绝，不宣称实现全部新版协议功能。
- 公共 TS 绑定使用 `.js` 相对导入，支持严格 NodeNext 消费；保留现有公开子路径，整理生产模块和测试职责。请求/响应绑定形状与 npm 0.1.0 相比不变，不引入旧分支独立 MCP 包或第二套端口。

### 接入与兼容性

- 同时使用的 Aether npm 包统一锁定 `0.1.1`，例如 `pnpm add --save-exact @ouraihub/aether-ui@0.1.1 @ouraihub/aether-worker@0.1.1`；内部依赖由发布流程固定到本次版本。UI 继续要求 Svelte 5，包提供 TS/Svelte 源码，由宿主构建，不是预编译浏览器脚本。
- Rust 宿主使用 `v0.1.1` tag 或该 tag 对应固定提交，并同步所有 Aether crate 来源。旧版职责重构前的宿主须按 [迁移与验收](24-详细设计-职责分层与实现契约.md) 一次迁移，不保留旧 API 兼容层。
- MCP 的 scope 缩减对后续请求生效；增加 scope 不会自动扩大旧令牌权限，客户端须重新授权。业务资源拒绝不等于缺 OAuth scope，不能靠重新授权绕过。
- 生产 Worker 仍需宿主身份、CSRF、资源授权和可信出站网关；此次发版不替代这些部署前置。

### 契约与存储版本

公开合同以 [跨运行时公共契约](22-详细设计-跨运行时公共契约.md) 和 `contracts/manifest.json` 为准，`contractVersion = 1`；RunRequest/RunAccepted/RunEvent/RunSnapshot、错误及会话 DTO 不变。本次不新增数据库迁移。

| Native Conversations `chat.db` | 6 |
| Native Skills `skills.db` | 2 |

### 升级与回退

1. 先停止写入并备份数据库、文件/R2 对象、配置及凭据恢复条件，再升级全部关联包和宿主锁文件。系统 Keychain/Secret Service 的主密钥不包含在普通数据库备份里，不能承诺跨系统直接复制密文可用。
2. 本版没有新 migration；已有数据库仍执行各模块原有版本校验。不得通过清库、降 `user_version` 或吞掉 `incompatible_db` 强行启动。
3. 回退时整体恢复原宿主提交、原 Aether 固定版本与锁文件；若数据库曾由更旧版本升级或新数据已写入，先评估旧版本可读性，必要时恢复升级前一致备份。不要混用新 Worker/UI 与旧 contracts/core，也不自动删除新写入数据。
4. npm 0.1.0 保持不可变，不覆盖、不撤包；回退锁定旧版本。撤销的 token 不因回退而保证恢复，客户端可能需要重新授权。
