# 21 详细设计：共享模型服务预设

> 状态：已定方案，待实现。适用：Aether 的多个桌面宿主（AutoBee、AutoNote 等）。
> 目标：共享公共模型服务商的非敏感连接信息，不共享应用配置、用户密钥或数据库。

## 1. 结论

新增独立 npm 包 `@ouraihub/aether-presets`，与 `@ouraihub/aether-ui` 同属 Aether workspace。

- `@ouraihub/aether-ui`：定义 `ProviderPreset` 合同，提供 `ProvidersSettings` 组件。
- `@ouraihub/aether-presets`：提供公共预设数据和按场景分组的导出。
- 宿主应用：选择需要的预设集合，通过 `<ProvidersSettings presets={...} />` 传入。
- `aether-providers`：负责 `presetId` 持久化、幂等创建、同名服务商接管和预设不可删除。

预设是编译期随版本发布的静态数据，不做运行时远程下载。

## 2. 为什么单独成包

预设数据不是 UI 组件职责，也不是 Rust provider 存储职责。独立包避免：

1. 每个宿主复制同一份服务商列表；
2. `aether-ui` 绑定具体商业服务商；
3. 修改预设数据时触发 UI 组件版本变更；
4. 远程配置被篡改后影响所有宿主；
5. 预设地址和 UI 行为混在一个模块里难以审计。

预设包只包含公共连接元数据，不包含任何用户秘密。

## 3. 数据合同

复用 `@ouraihub/aether-ui/ports` 的 `ProviderPreset`，不定义第二个相似类型：

```ts
export interface ProviderPreset {
  id: string
  name: string
  baseUrl: string
  protocol: Protocol
  apiKeyUrl?: string
}
```

字段规则：

- `id`：永久稳定的机器标识，不随名称变化；用于 `presetId` 和数据库唯一约束。
- `name`：展示名称，可随版本修正。
- `baseUrl`：新建预设服务商使用的默认地址。
- `protocol`：预设协议；不存 API key。
- `apiKeyUrl`：可选的获取密钥链接，只能是维护者确认的 HTTPS URL。

禁止字段：API key、用户账号、默认启用状态、用户模型列表、角色绑定、用户密钥链接中的临时 token。

## 4. 导出分组

预设包按宿主场景导出，不要求所有宿主展示全量列表：

```ts
import { CHINA_PROVIDER_PRESETS } from '@ouraihub/aether-presets/china'
import { INTERNATIONAL_PROVIDER_PRESETS } from '@ouraihub/aether-presets/international'
```

第一期 `china` 包含：

| id            | 名称     | 地址                            | 协议          |
| ------------- | -------- | ------------------------------- | ------------- |
| `qiniu`       | 七牛云   | `https://api.qnaigc.com`        | `openai-chat` |
| `siliconflow` | 硅基流动 | `https://api.siliconflow.cn/v1` | `openai-chat` |
| `fenno`       | Fenno    | `https://api.fenno.ai/v1`       | `openai-chat` |

国际预设集合留作后续真实需求，不提前填充猜测数据。

根入口同时导出 `PROVIDER_PRESETS`，但宿主优先使用明确的分组入口，避免无意展示不适合本产品的服务商。

## 5. 初始化和用户数据规则

`ProvidersSettings` 在加载列表后，对每个传入预设调用一次 `ProviderSave`：

```ts
{
  name: preset.name,
  presetId: preset.id,
  enabled: false,
  endpoints: [{
    slug: 'ep-1',
    baseUrl: preset.baseUrl,
    protocol: preset.protocol,
    models: [],
  }],
}
```

后端保证：

1. 已存在相同 `presetId`：返回当前列表，不创建重复行；
2. 已存在同名且没有 `presetId` 的用户服务商：绑定该行，不覆盖名称、地址、协议、模型和密钥；
3. 其他情况：创建禁用、无密钥、无模型的新行；
4. 带 `presetId` 的服务商不可删除；
5. 更新预设包地址不会覆盖已有用户配置；只影响新建行；
6. 删除预设包不会删除用户数据库中的既有行。

数据库和密钥仍按每个宿主的 `data_root` 隔离，不跨应用共享。

## 6. 版本和发布

- 预设包与 Aether 使用同一 git commit/tag 发布。
- 宿主固定不可变 Aether commit，不使用浮动 `main`。
- 修改地址、协议或获取密钥链接必须更新 changelog，并说明是否影响新建行或仅影响展示。
- 移除预设只移除新宿主的自动创建入口，不删除用户数据。
- 预设链接变更必须在 CI 做 HTTPS 和重复 `id` 检查。

## 7. 安全边界

- 预设包是代码依赖，不是远程配置中心；供应链由 git commit、lockfile 和 CI 审计。
- `apiKeyUrl` 仅用于用户主动打开链接，不携带本地 API key，不把密钥拼到 URL。
- 预设不改变默认启用状态；新行默认禁用，必须由用户填写密钥后主动启用。
- Aether provider 的 URL 校验、MCP 信任和密钥加密规则继续有效。

## 8. 宿主接入示例

```svelte
<script lang="ts">
  import { CHINA_PROVIDER_PRESETS } from '@ouraihub/aether-presets/china'
  import { ProvidersSettings } from '@ouraihub/aether-ui/providers'
</script>

<ProvidersSettings presets={CHINA_PROVIDER_PRESETS} />
```

宿主不复制预设对象，不修改 `presetId`，也不直接调用 provider store 的内部 API。

## 9. 不做的事

- 不做远程动态预设下载；
- 不做 API key 同步；
- 不做跨应用共享 providers.db；
- 不自动探测或保存预设模型；
- 不自动启用预设；
- 不把应用专属服务商塞进共享包。

这些需求只有在出现明确的运营、企业分发或服务商目录管理需求时再单独设计。
